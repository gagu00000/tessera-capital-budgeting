# TESSERA

**Should a studio own its intelligence, or keep renting it?**

An AI-enabled capital budgeting appraisal of a AED 7.06 million GPU inference
cluster — built, verified, and argued end to end.

Corporate Finance individual assignment · Masters in Artificial Intelligence
with Business · SP Jain School of Global Management, Dubai
Author: **Gagandeep Singh**

---

## The decision

A 34-person animation and VFX studio in Dubai is spending a growing amount on
rented GPU capacity for AI-assisted production work. The question is whether to
buy the hardware instead. Four alternatives are appraised:

| | Alternative | Outlay (AED) | Life |
|---|---|---|---|
| **A** | Buy 32 GPUs outright | 7,060,000 | 5 years |
| **B** | 3-year reserved cloud commitment | 45,000 | 3 years |
| **C** | Hybrid — own 16, burst to cloud | 3,830,000 | 5 years |
| — | Do nothing (on-demand cloud) | — | — |

The base case does not settle it. Alternative A's NPV is **−AED 51,476**, which
is 0.73% of the outlay — inside the margin of error of the assumptions
themselves. What settles it is the break-even: NPV break-even requires **85.4%**
peak utilisation against a plan of **85.0%**. The project needs the cluster to
run essentially exactly as forecast, for five years, merely to be worth
building.

## Verification

Every figure the application reports is checked three ways.

1. **Unit tests** — 69 cases whose expected values were derived by hand, with
   the longhand working kept in the test file rather than copied from the
   implementation.
2. **A second implementation** — `verification/verify_model.py` recomputes the
   whole model independently in Python against `numpy-financial`, and compares
   79 quantities across four cases. All 79 agree.
3. **Runtime consistency checks** — seven identities the model asserts about
   itself on every recomputation, so a bad edit surfaces in the interface rather
   than silently.

```bash
cd tessera && npm test          # 69 unit tests
cd tessera && npm run verify    # export the engine's results
cd verification && python verify_model.py
```

One disagreement was real. Python found an IRR for a non-conventional cash flow
series where the TypeScript solver returned null — not because it had detected
the multiple-root problem, but because its bracketing had failed. The solver now
sweeps for every root; that series has two (−37.79% and +439.01%), and the
interface says so rather than quoting one.

## The AI layer

Claude interprets the appraisal. It does not compute it.

The response schemas in `src/ai/schemas.ts` contain **no numeric fields at all**,
so there is no route by which an AI-invented figure could reach the page. Every
number is calculated and verified client-side, then handed to the model as
structured data.

Claude's recommendation is shown beside a **deterministic rule-based verdict**
computed in plain TypeScript from decision rules written down in advance, so
there is something independent to measure the model against. On this project
they disagree, and the interface says why.

`api/advisor.ts` exists for exactly one reason: the API key must never reach the
browser. It performs no calculation, so without it the appraisal still produces
every number and only the commentary degrades — falling back to pre-authored
text that is badged **"Pre-generated"** rather than passed off as a model
response.

## Running it

```bash
cd tessera && npm install && npm run dev
```

For live Claude responses, set `ANTHROPIC_API_KEY` as a **server-side**
environment variable (in Vercel: Project → Settings → Environment Variables).
Without it the application runs completely, on the fallback commentary.

```bash
npm run typecheck   # tsc -b across app, api and scripts
npm test            # unit tests
npm run build       # production build
npx vite-node scripts/screenshots.ts   # regenerate the report figures
```

## Built with

React 19 · TypeScript · Vite · Tailwind CSS v4 · Zustand ·
react-three-fiber + three.js · framer-motion · GSAP · Vitest · Playwright ·
Anthropic SDK (`claude-opus-5`)

library, so the axes, the diverging colour scale anchored at zero, and the
switching-value markers do exactly what the analysis needs.
